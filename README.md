# DRQA

**Diagnose · Resolve · Quality Assurance**
פלטפורמה אינטראקטיבית לאבחון תקלות API ולהנדסת QA

DRQA עוזרת למהנדסי QA לחקור תקלות API, להבין התנהגות HTTP, לבחון בקשות ותגובות, לתרגל תרחישים מציאותיים, לתכנן מקרי בדיקה ולכתוב דיווחי באג מקצועיים. כל חקירה מפרידה בין **עובדות שנצפו**, **השערות**, **הנחות לא מאומתות** ו**ממצאים מאומתים**.

> כל הנתונים באפליקציה בדויים: חנות בשם **Demo Shop** ונקודות קצה תחת `api.example.com`. אין קשר לאף ארגון אמיתי.

---

## פרטיות

- האפליקציה סטטית לגמרי: אין שרת, אין מסד נתונים, אין אנליטיקס ואין טלמטריה.
- **אף בקשה לא נשלחת לרשת.** מעבדת הבקשות מחשבת את התגובות מקומית בדפדפן לפי חוקים קבועים.
- תוכן שאתם מזינים (JSON, בקשות, דיווחי באגים) לא נשמר. רענון הדף מוחק אותו.
- הדבר היחיד שנשמר ב-`localStorage` הוא בחירת ערכת הנושא (בהיר או כהה).
- הגופנים (Heebo, JetBrains Mono) נארזים יחד עם האפליקציה, כך שאין קריאה ל-Google Fonts.

## הרצה מקומית (Windows + VS Code)

דרישות: [Node.js](https://nodejs.org) גרסה 20 ומעלה (נבדק על גרסה 24), ו-Git.

```powershell
git clone https://github.com/<your-user>/drqa.git
cd drqa
npm install
npm run dev
```

אחרי ההפעלה, פתחו את הכתובת `http://localhost:5173/drqa/`.

ב-VS Code: **File ← Open Folder** ובחירת התיקייה, ואז הרצת הפקודות במסוף המובנה (`` Ctrl+` ``).

| פקודה | מה היא עושה |
|---|---|
| `npm run dev` | שרת פיתוח עם רענון חי |
| `npm test` | הרצת בדיקות היחידה (Vitest) |
| `npm run typecheck` | בדיקת טיפוסים של TypeScript |
| `npm run build` | בדיקת טיפוסים ובנייה לתיקיית `dist/` |
| `npm run preview` | הגשה מקומית של הבנייה (`http://localhost:4173/drqa/`) |

## פריסה ל-GitHub Pages

הפרויקט מוגדר לפריסה תחת שם המאגר **`drqa`**:

- ב-`vite.config.ts` מוגדר `base: '/drqa/'`.
- הניתוב מתבצע עם `HashRouter`. כתובות נראות כמו `/drqa/#/api-doctor`, כך שרענון וקישור ישיר עובדים בלי הגדרות שרת.

**שלבים:**

1. צרו ב-GitHub מאגר בשם `drqa` ודחפו אליו את הקוד לענף `main`:
   ```powershell
   git add .
   git commit -m "DRQA initial version"
   git branch -M main
   git remote add origin https://github.com/<your-user>/drqa.git
   git push -u origin main
   ```
2. במאגר, היכנסו ל-**Settings ← Pages ← Build and deployment ← Source** ובחרו **GitHub Actions**.
3. ה-workflow בקובץ `.github/workflows/deploy.yml` מריץ את הבדיקות, בונה את האפליקציה ופורס אותה בכל push ל-`main`.
4. האתר יהיה זמין בכתובת `https://<your-user>.github.io/drqa/`.

> אם תשנו את שם המאגר, עדכנו את `base` ב-`vite.config.ts` ואת נתיב ה-favicon ב-`index.html`.

**עקרונות:**

- **הפרדה בין חוקים לתצוגה.** עצי ההחלטה, הסימולטור, מחולל הבדיקות ולוגיקת הדיווח הם פונקציות טהורות עם טיפוסים, ונבדקות ללא UI.
- **מנוע אבחון דטרמיניסטי.** המצב של חקירה הוא רק מפה של `nodeId → optionId`, והמסלול מחושב מחדש מההתחלה בכל שינוי. כך שינוי תשובה קודמת מנתב מחדש את העץ באופן אוטומטי.
- **ספריות משותפות.** ההשערות והבדיקות המומלצות מוגדרות פעם אחת, ומשמשות גם את API Doctor וגם את חוקר התקלות.
- **בלי תלויות מיותרות.** הדגשת התחביר ומאמת הסכמה נכתבו בפרויקט עצמו. תלויות זמן הריצה הן רק React, React Router, Lucide וקובצי הגופנים.

## בדיקות ובנייה

- **בדיקות יחידה:** 120 בדיקות ב-8 קבצים.
  - ניתוב בעצי ההחלטה, כולל מעבר על **כל** המסלולים האפשריים בכל 20 העצים ובדיקה שכל הפניה תקינה.
  - בחירת תרחיש בסימולטור, כולל בדיקה שאין קריאה ל-`fetch` או ל-`XMLHttpRequest`.
  - עיצוב והשוואת JSON.
  - אימות חוזים.
  - יצירת דיווח באג.
  - יצירת מקרי בדיקה.
  - השוואת קונפיגורציית סביבות וחיפוש.
- **TypeScript:** `tsc --noEmit` עובר ללא שגיאות (מצב strict).
- **בנייה:** `vite build` מצליחה. כל מודול נטען בנפרד (code splitting). החבילה הראשית שוקלת כ-145KB אחרי gzip.
- **בדיקה בדפדפן:** נבדק ב-Chrome headless מול הבנייה המקומית בכל 18 הנתיבים, ברוחב 1440px וברוחב 390px:
  - לא נמצאו שגיאות קונסול ולא נמצאה גלילה אופקית.
  - לא נשלחה אף בקשת רשת חיצונית.
  - נבדקה זרימה מלאה: חקירה ב-API Doctor, שינוי תשובה קודמת, שליחה מהמעבדה, חיפוש `Ctrl+K`, החלפת ערכת נושא ואשף הדיווח.
  - **לא בוצעה** בדיקה ידנית בדפדפנים אחרים, ולא בוצעה בדיקה עם קורא מסך.

## מגבלות ידועות

- הסימולטור מכסה רק את ה-API הבדוי. אי אפשר לשלוח איתו בקשות אמיתיות, וזה מכוון.
- מאמת הסכמה תומך בתת-קבוצה של JSON Schema. מילות המפתח `$ref`, `oneOf`, `anyOf`, `allOf` ו-`if/then` אינן נאכפות, והמאמת מציג אזהרה כשהן מופיעות.
- התוכן שמוזן לא נשמר בכוונה. רענון הדף מוחק חקירה או דיווח שלא יוצאו.
- רשימת "בשימוש לאחרונה" נשמרת רק בזיכרון של הסשן הנוכחי.
- התוכן כתוב בעברית בלבד, בלי מנגנון תרגום.
- הנגישות נבנתה לפי עקרונות סמנטיים: ניווט מקלדת, focus גלוי, ARIA וכיבוד prefers-reduced-motion. עדיין לא בוצע מבדק נגישות פורמלי.

## צעדי פיתוח מומלצים

1. שמירה אופציונלית ומפורשת של חקירות ב-localStorage, עם אפשרות מחיקה.
2. ייבוא קובץ HAR (שיעובד מקומית) למעבדה ול-API Doctor.
3. תמיכה ב-`$ref` וב-`oneOf` במאמת, או מעבר לספרייה כמו Ajv.
4. בדיקות קצה-לקצה עם Playwright ובדיקות נגישות עם axe-core ב-CI.
5. ייבוא מפרט OpenAPI ל-Test Designer ול-Contract Validator.
6. גרסה באנגלית (i18n).
